# MadStory 导演级预检清单 (Director Pre-Flight Checklist)

启用 MadStory 技能前，使用以下清单进行创作准备度验证。

## 1. 技术规格 (Technical Specifications)

- [ ] **Mode 已确认** — 11 个模式中选定 1 个 (creative_film / ecommerce / ugc / cinematic / multi_shot / one_shot / viral_replicate / agent_mode / short_drama / smart_edit / white_model)
- [ ] **引擎版本已确认** — Seedance 2.5（默认）或 2.0（降级）。降级时确认未误用 2.5 独有能力
- [ ] **Seedance 输入模式已推荐** — 全能参考 / 智能编辑 / 超长视频 / 首尾帧（2.5 四选一）；或 Text-to-Video / Image-to-Video / Reference-to-Video（2.0）
- [ ] **时长已设定** — 2.5 默认 30s，超长模式 30-180s，视频延长 ≤60s；降级 2.0 时 15s
- [ ] **画幅比例已确定** — 16:9 / 9:16 / 1:1 / 2.35:1
- [ ] **Motion Strength 已建议** — 按模式: Ecommerce=2 / UGC=3 / Cinematic=5 / Multi-shot=4 / One-shot=4 / Viral=5 / Drama=4 / Smart Edit=3 / White Model=3

## 2. 主体与构图 (Subject & Composition)

- [ ] **主体已明确** — 产品 / 人物 / 场景，不可含歧义
- [ ] **单镜头信息点检查** — 每个镜头只承载 1 个动作或 1 个信息点
- [ ] **构图方式已确定** — 三分法 / 中心 / 对称 / 对角线 / 框架式
- [ ] **产品占比检查 (Ecommerce)** — 产品占画幅 ≥ 40%，不在边角
- [ ] **取景范围检查 (UGC)** — 半身/特写已确定，自然取景非影楼感
- [ ] **多镜头场景检查 (Multi-shot/One-shot)** — 每段含: 主体 + 动作 + 机位

## 3. 镜头运动 (Camera Movement)

- [ ] **单运动原则检查** — 每个镜头 ≤ 1 个主导运动
- [ ] **运动类型已选择** — orbit / dolly / push-in / pull-out / crane / handheld / whip / follow / static
- [ ] **运动动机已明确** — 每次运动服务于叙事/产品目的
- [ ] **时间轴运动标注** — 在 Timeline 上标注运动变化节点
- [ ] **运动强度在合理范围** — Ecommerce ≤ 3 / UGC = 3 / 其他 4-5

## 3.5 表演与调度 (Performance & Blocking)

- [ ] **走位已定义** — 角色在空间中的位置/移动路径有叙事理由
- [ ] **视线匹配已检查** — 对话/对视场景中视线方向与对手匹配
- [ ] **反应镜头已规划** — 关键情绪转折点有反应镜头安排（如适用）
- [ ] **潜台词已标注** — 表里不一的角色有视觉暗示处理（如适用）
- [ ] **短剧标志性动作** — 角色档案中的 habits 已安排出现时机（Mode 8）

## 4. 光影与色彩 (Lighting & Color)

- [ ] **光源方向已确定** — key light 方向、fill ratio
- [ ] **色温已指定** — 暖色 (3200K) / 中性 (4500K) / 冷色 (5600K+)
- [ ] **灯光类型已选择** — 三点布光 / 蝴蝶光 / 伦勃朗 / 侧光 / 逆光 / 霓虹 / 金色时刻
- [ ] **环境细节已描述** — 烟雾/颗粒/反射/材质
- [ ] **电商光位检查** — 光源不遮挡或反射产品标签
- [ ] **UGC 光感检查** — 自然光/环形灯，不过度打光
- [ ] **色彩调性一致** — 跨镜头保持一致的色彩氛围

## 5. 声音设计 (Sound Design)

- [ ] **BGM 情绪已确定** — 激昂/舒缓/悬疑/科技感/自然/电子
- [ ] **音效同步点已标注** — 与 Timeline 关键帧对齐
- [ ] **环境音已规划** — 雨声/风声/人群/房间音
- [ ] **电商/多镜头模式** — BGM 不打断产品信息传达

## 6. 模式专项检查 (Mode-Specific)

### Ecommerce (电商)
- [ ] 产品标签可读性已声明 (Negative Prompt)
- [ ] 产品几何保护已声明 (no warped, no distortion)
- [ ] Image-to-Video 模式已推荐
- [ ] 白底/纯色背景已指定

### UGC (原生广告)
- [ ] 人脸一致性已声明 (no face drift)
- [ ] 手指保护已声明 (no extra fingers)
- [ ] Reference-to-Video 模式已推荐
- [ ] 社交节奏感已描述

### Cinematic (电影感)
- [ ] 镜头抖动保护已声明
- [ ] 灯光逻辑有明确动机
- [ ] 单一情绪 payoff 已识别
- [ ] 物体变形保护已声明

### Multi-shot (多镜头)
- [ ] 镜头数 ≤ 3
- [ ] 过渡关键词已使用 (Cut to / Camera cut to / Shot Switch)
- [ ] 跨镜头一致性约束已声明
- [ ] 时间分配合理 (各镜头时长和 = 总时长)

### One-Shot (一镜到底)
- [ ] 图片数 2 ≤ N ≤ 10
- [ ] 转场类型已逐段指定或设为 Auto
- [ ] 空间连续性已声明 (no spatial discontinuity)
- [ ] 跳帧保护已声明 (no stutter)

### Viral Replicate (爆款复刻)
- [ ] 参考视频已指定
- [ ] 复刻策略已选定 (creative/classic/deconstruct)
- [ ] 替换主体已指定 (如适用)
- [ ] 风格偏离保护已声明 (no style drift)

### Agent Mode (Agent)
- [ ] 用户意图已解析 (风格/时长/情绪)
- [ ] 路由决策已执行
- [ ] 子模式的 Negative Prompt 已注入
- [ ] 输出模式标签包含子模式信息

### Short Drama (短剧)
- [ ] 角色注册表已建立
- [ ] @角色引用机制已启用
- [ ] 跨集一致性约束已声明
- [ ] 剧本格式已验证 (场景/人物/△/OS)
- [ ] 一致性管控台账已建立 (Characters / Scenes / Timeline)
- [ ] 长戏份 (>30s) 已拆分标记校验节点（2.5 基准；2.0 降级时 >15s）
- [ ] 人物档案六项不可变字段已填写 (视觉标记/发型发色/妆容/服饰/配饰/穿着状态)
- [ ] 场景清单四项环境参数已记录 (光线方向/色温/天气/背景杂音)
- [ ] 后期跨片段一致性校验已规划 (C1/C2/C3)
- [ ] (2.5) 多人场景已用多人参考，每个角色独立轮廓/五官/气质/穿搭
- [ ] (2.5) 角色音色已绑定 @音频参考
- [ ] (2.5) 多语种版本已用母语写台词 + 强制语言输出声明

### Smart Edit (智能编辑 — 2.5 专属)
- [ ] **编辑对象已精准定位** — 具体修改对象明确，未用模糊代词
- [ ] **变化描述为 A→B** — 写清从什么变成什么（如牛仔裤→西装裤）
- [ ] **生效时序已标注** — 全片统一 / X-Ys 期间 / 从第 N 秒起
- [ ] (高级编辑) 标注工具与方位已指定 — 框/线/箭头/文字/地标点 + 内/外
- [ ] **保留不变要素已声明** — `保持其他不变`、`人物本人/皮肤/头部/手脚/身体姿态/运动动作保持不变`
- [ ] **移除后补全已声明** — `原本被遮挡的[地毯/墙面]需要自然补全，不能留下残影或模糊补丁`
- [ ] BGM 分离/去字幕场景已明确指令 — `去除背景音乐，保留清晰的人声` / `纯净视频，无字幕，无背景音乐`
- [ ] 绿幕编辑已指定目标背景描述

### White Model (白模预演 — 2.5 专属)
- [ ] **颗粒度已选择** — 粗颗粒度（从零生成）/ 细颗粒度（材质替换渲染）
- [ ] (粗颗粒度) 参考声明已写 — 参考视频的运镜/动作/动线/光影/站位/节奏
- [ ] (粗颗粒度) 对应关系映射已写 — 将白模的{颜色/形状}替换为[图X]的{角色名}
- [ ] (粗颗粒度) 若有四肢/翅膀，完整动作序列已写（最佳实践：不上传有四肢/翅膀的模型）
- [ ] (细颗粒度) 渲染指令已写 — 将白模动画渲染成最终成片
- [ ] (细颗粒度) 分段渲染描述已写 — 每段背景/色调/人物材质/光影 + 转场触发点
- [ ] 参考视频已去除轨迹线/坐标线/相机 cone 等干扰信息

## 7. 多模态输入检查 (Multi-Modal Input)

- [ ] Reference 图已分配角色 — Image1(主身份), Image2(辅助), Image3(色调)
- [ ] 多个 Reference 之间光位/造型/质量对齐
- [ ] Reference 不与模糊 prompt 搭配使用
- [ ] 手部在画面中时已在 Negative Prompt 中保护
- [ ] **素材上限检查** — 2.5: ≤30 图 + ≤10 视频 + ≤10 音频（总≤30s）/ 2.0 降级: ≤9 图 + ≤3 视频 + ≤3 音频（总≤15s）
- [ ] (2.5) @标签已绑定到具体 beat — @图片1/@视频1/@音频1
- [ ] (2.5) 音色参考 — 上传清晰无杂音人声 + 文案 + 语调描述
- [ ] (2.5) 多人参考 — 每角色独立轮廓/五官/气质/穿搭，提示词明确各角色动作与关系
- [ ] (2.5) 仅传音频场景已确认（2.5 支持；2.0 不支持，必须配图/视频）
- [ ] 稳定性经验值已参考 — 主体图 1-8 张效果好（9-12 需抽卡），主体音视频 1-5 个效果好（6-10 需抽卡）

## 8. 输出完整性检查 (Output Integrity)

- [ ] **ENGINE_VERSION 已标注** — Seedance 2.5（默认）或 2.0（降级），降级时不可用能力已声明
- [ ] **STANDARD_PROMPT 符合 4 段式** — 素材描述+一句话概述+具体情节+全局补充（专项场景用对应公式）
- [ ] **NEGATIVE_PROMPT 按模式自动注入完整** — 2.5 用"禁止"表述，2.0 用 `no xxx`
- [ ] **TIMESTAMP_CONTROL 已输出** — 长视频/多镜头/卡点场景必填（2.5 专属，2.0 降级时跳过）
- [ ] TIMELINE 含关键帧描述 — 2.5 默认 30s，超长 30-180s，延长 ≤60s，2.0 降级 15s
- [ ] CAMERA 逐秒/逐镜头描述
- [ ] MOTION_STRENGTH 在 1-10 范围
- [ ] DURATION 含时间单位
- [ ] MODE 标签正确
- [ ] MULTI_MODAL_ADVICE 具体可用（2.5/2.0 上限已区分）
- [ ] SHOT_LIST 完整 (多镜头模式)
- [ ] **5 层元素检查清单已逐项过** — Subject/Single Action/Camera/Style/Constraints
- [ ] **版本能力匹配已检查** — 降级 2.0 时未误用 2.5 独有能力（时间戳/编辑/白模/超长/延长/BGM分离/多语种/多人/绿幕）

## 9. 质量护栏检查 (Quality Gates)

- [ ] Negative Prompt 非空
- [ ] 每个 Mode 的专项护栏已触发检查
- [ ] 无任何 FAIL 级别的质量问题

- [ ] 广告视角确认 (如适用): 这个素材适合直接投放吗？
- [ ] 即梦视角确认: 这个提示词在 Seedance 2.5 中能直接使用吗？降级 2.0 时参数和能力是否兼容？
- [ ] 一致性确认: 多镜头/多素材间风格统一吗？
- [ ] (可选) 使用独立校验工具验证: `tools/mad-story-scripts/`

## 12. 元反思 — 推演过程自检（v3.5 新增）

> 以上 1-11 检查的是分镜方案本身的完整性和合规性。本节跳出"检查方案"的视角，转而审视 **整个创作推演过程是否站得住脚**。逐维度回答，每个维度必须在 Phase 0-7 的推导中找到具体依据。

| 维度 | 核心问题 | 在分镜创作中的具体含义 |
|------|---------|----------------------|
| **问题定义** | 我是否理解了真正的问题？有没有更好的问题表述？ | Phase 0 锁定的 Mode 是否命中用户的真实意图？用户说"电商视频"时真正要的是转化素材还是品牌背书？是否存在更准确的问题框定（如把"品牌短片"重新定义为"15 秒品类心智植入"）？ |
| **假设** | 我的关键假设是什么？哪些未经验证？ | 分镜方案隐含了哪些假设（目标平台播放环境、用户有 Seedance/Runway 特定版本可用、参考图质量、观众先验认知、品牌调性理解）？哪个假设一旦不成立，整个分镜方案就会失效？ |
| **推理** | 推理链是否存在跳跃、循环或逻辑漏洞？ | Phase 1→7 的推导链是否有跳跃（如"品牌年轻化"直接跳到"赛博朋克视觉"跳过了品牌调性验证）？Camera 运动是否有理由（是否真的服务叙事，还是术语炫技）？Timeline 节奏分配是否只是 AI 默认而非真正思考过？ |
| **证据** | 哪些观点有证据支持？哪些只是推测？ | 光影选择、构图方式、运镜类型是基于导演风格数据库（cheat_sheet.json / cs_core.json）还是 AI 模型记忆？Mode 专项约束是否基于真实平台经验还是 AI 假设？Motion Strength 建议是校准过的还是启发式默认？ |
| **替代解释** | 是否存在其他同样合理甚至更好的解释？ | 当前的视觉方案是否是众多可行方案中最好的那个？Tournament 筛选出的方案是否只是因为"更安全"而非"更好"？是否还有其他未被考虑的视觉风格方向同样能服务同一叙事目标？ |
| **边界条件** | 结论适用于哪些场景？什么时候会失效？ | 本分镜方案在什么条件下成立？何时会失效（Model 版本升级后提示词失效、参考图更换后风格崩坏、夜间播放环境色温偏移、竖屏转横屏布局破坏）？ |
| **目标** | 当前优化目标是否正确？是否应该优化更高层目标？ | 当前目标是"生成一个专业的分镜方案"，但是否应转向更高层目标（方案是否匹配用户的实际生成工具版本、是否考虑了用户团队的实际执行能力、是否该建议降级为更简单的 Mode 而非强推复杂度）？ |
| **不确定性** | 我最没有把握的部分是什么？还需要哪些信息才能提高可信度？ | 本次分镜推演最薄弱的环节是什么（光影？声音？跨镜头一致？Mode 匹配度？）？补充哪些信息（用户参考视频、实际 Seedance 版本、目标植入平台规格、用户过往作品风格偏好）能显著提升方案可信度？ |

### 元反思约束（Hard Constraints）

以下约束强制执行，违反任何一条必须回退修正：

1. 元反思必须基于 Phase 0-7 的实际推导内容，**逐条对应到具体 Phase**，不得写成与本案无关的泛泛之谈
2. `问题定义` 判定为 reframe_needed 时，更优框定不得为空
3. `假设` 至少识别出 **1 个** 隐含关键假设；标注未验证的假设不得为空
4. `推理` 中任何一条缺陷的定位必须精确到 Phase + 推导环节（如"Phase 3 构图选择→Phase 4 运动类型跳跃"），不得笼统写"推导有跳跃"
5. `推理` 整体判定为 broken 时，**必须在最终输出顶部显著标注** "⚠️ 本次分镜推演存在推理链断裂，方案可靠性存疑，建议重新审视 Phase 推导"
6. `证据` 中"仅推测的论点" **不得为空**——至少列出 1 个仅靠 AI 模型记忆/启发式支撑的论点（Motion Strength 建议值、色彩调性选择本身即为启发式）
7. `替代解释` 中若存在合理性为"高"且与当前方案冲突的替代视觉方向，必须在输出中提示"存在高合理化替代视觉方向，当前方案并非唯一选择"
8. `目标` 判定为 consider_higher_goal 时，更高层目标建议不得为空，且必须可决策（不得填"考虑创作层面"这类空话）
9. `边界条件.失效情形` **不得为空**——必须列出至少 1 个分镜方案失效的真实情形
10. `不确定性.需补充信息` 必须可操作（具体到用户能执行的动作），不得填"需要更多信息"这类空话
